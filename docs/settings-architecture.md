# Общая основа редакторов свойств

## Три контекста и независимые сеансы — FUNC-032

Актуальная конфигурация: [карта сценариев](scenarios.md). createWidgetScenario({editor,id,context,seed,modeChanged}) создаёт независимый runtime, но использует один рендерер/ввод/команды/историю. site сохраняет прежнюю nullable FAQ-модель; standalone владеет document.widgets без parentId и скрытого FAQ. activate/deactivate ограничивают клавиатуру активной веткой и отменяют временные редакторы при уходе.

PG API минимально расширен getOwner/getItems/isStandalone/isActive/scenarioId; legacy getFaq возвращает реальный FAQ или null. Standalone main — конфигурация общих строк, typography/button/size и styleCard. Самостоятельный сеанс пишет собственные settings.propertyGrid, вложенный FAQ-спойлер сохраняет прежние sparse overrides. Предварительный paintGroup общий, привязка разная. Выборы ограничены прямоугольником активного продукта, системная область не входит в viewport редактора.

## Отсутствие FAQ и магазин — FUNC-031

state.faq может быть null. documentSnapshot/restoreDocument сохраняют/возвращают отсутствие объекта наряду со всеми прежними данными; makeFaq создаёт новый объект, не подменяя старые ID. PG getFaq/itemById/commonSettings/paint/open проверяют отсутствие владельца. Открытый сеанс отменяется до удаления; его черновик не переносится на новый FAQ. DOM-адаптер FAQ и делегированные обработчики используются повторно, отсоединённая оболочка без спойлеров не является активным FAQ. Инициализация демонстрации только при загрузке — docs/demo-startup.md.

createWidgetStore — один внешний слой редактора, не новая система PG. beforeOpen отменяет PG; surfaceChanged закрывает магазин при открытии редактора. Null/доступность цели задаётся API и проверяется снова перед вставкой. Поиск/панель не создают историю. Открытые панели закрываются при Undo/Redo смены объекта и переходе в preview. Escape магазина не сворачивает одновременно ответ в режиме overlay.

## Контекстное меню и единая диспетчеризация — FUNC-029

`open('menu',anchor)` разрешён для FAQ и спойлера. openMenu фиксирует {type,id,parentId} отдельно от выделения и не редактирует draft. menuFor/context меняет только состав, menuMarkup/слой/стили/expander общие. Свёрнутая высота152/266px используется при viewport-clamp, поэтому expand не сдвигает верх.

Разрешения menu централизованы в canMenuCommand отдельно для двух типов. Рабочая строка сначала копирует context, отменяет/закрывает menu, затем вызывает api.runCommand. Общий runCommand preview.js проверяет mode/target/parent/актуальность выбора и вызывает прежние add/delete/редакторы. Тот же dispatcher обслуживает toolbar, без synthetic DOM click. После открытия нового редактора фокус устанавливает его прежний механизм; close menu уже завершён. Заглушки не вызывают dispatcher и не меняют документ/буфер. История только у фактических document-команд/сохранения редактора, не у menu UI.

## Прямой T для обоих владельцев — FUNC-028

open('typography',anchor) теперь доступен для selection.type faq или spoiler. Существующие transaction.type/id определяют область действия, entry.kind=typography — toolbar-контракт Back/cancel с отменой и закрытием. Из PG спойлера entry.kind остаётся properties, поэтому тот же уровень typography возвращается в main без потери draft. Position использует прежнее совмещение центров T и Back, а выбор/цвет — тот же текущий сеанс. Сохранение через writeIndividual не копирует унаследованные свойства; новая история/наследование/форма не создавались.

## Владелец-спойлер и индивидуальные значения — FUNC-027

Один экземпляр createFaqPropertyGrid обслуживает два типа владельца: `transaction.type='faq'|'spoiler'`, стабильный `id`, один original/draft и прежние вложенные окна. Для спойлера основной main выбирает spoilerMain; typography/button — существующие представления. Back из них возвращает в main этого владельца, прямой вход T сохраняет прежнюю отмену/закрытие. Положение рассчитывается по выбранному спойлеру с прежними scale/scroll/viewport.

`item.settings.propertyGridOverrides` — разреженная карта путей question/answer/button/spoilerStyle. Открытие не создаёт её и не копирует туда общие значения. `effectiveSettings(item)` объединяет текущие общие значения с индивидуальными; типографика нормализуется к фактически используемому стилю, поэтому изменение одного размера не фиксирует все унаследованные параметры шрифта. Старые копии item.settings.propertyGrid не считаются индивидуальными правками.

Подтверждённый пользователем контракт: общая правка заменяет соответствующее свойство у всех, включая индивидуальное. `markCommon`/changedPaths/replaced фиксируют изменённые или явно применённые свойства; preset заменяет прежний управляемый набор question/button/spoilerStyle. Preview временно исключает соответствующие overrides, отмена возвращает их; save удаляет эти overrides и записывает общий draft в одном существующем шаге истории. Несвязанные индивидуальные свойства сохраняются. Даже явный выбор прежнего значения FAQ заменяет отличающееся индивидуальное; открытие/закрытие без правок остаётся no-op.

Сброс индивидуального main возвращает наследование актуальных question/answer/button/spoilerStyle FAQ; typography — question/answer, button — button.editor. Локальный сброс цвета тоже использует родительское значение (включая отсутствие фона); для unset-state кнопки восстанавливает существующее наследование состояния от rest. Optional border/radius по-прежнему удаляются в чипсы, повторно добавляются с согласованными defaults, это отдельная команда от сброса. Индивидуальное save хранит только отличия, cancel ничего не записывает. Общий app Save подтверждает текущего владельца перед preview.

`settings()` возвращает общие значения для раскладки FAQ; `itemSettings(id)` — эффективные значения отдельного спойлера. paint применяет контейнер/разделители только из общих, оформление/тексты/кнопку — по каждому ID. Одни контролы styleCard/spoilerInset/buttonRow/textStyle/chooseColor получают эту же привязку draft. Строка кнопки скрывается по реальным button.visible/visibilityPolicy оформления, а не по текстовому стилю вопроса. Выбор другого объекта/удаление владельца отменяет сеанс.

Это локальный адаптер существующей модели PG, не отдельная библиотека наследования/истории. Размеры спойлера read-only без size-провала, тень/выбор гарнитуры/отдельные стороны и углы остаются недоступными.

## Просмотр ответа при открытом PG — FUNC-026

Единственное исключение защиты внешних событий видимой панели — `.spoiler-arrow` внутри редактируемого FAQ. Capture-handler передаёт click/Enter/Space в `api.toggleView(id)`, подавляет дальнейшее всплытие и сохраняет сеанс/выбор. Адаптер preview.js использует прежний toggle(item,true); новый параметр preserveSelection исключает выбор спойлера. Данные/история по-прежнему не содержат просмотрной открытости. Клики по тексту/ответу заблокированы, меню снаружи закрывается по прежнему правилу. Новых редакторов/обработчиков на каждое открытие нет.

`alignGuides()` после paint читает геометрию колонки/FAQ/спойлеров и записывает только служебные left/right inset; реальные стили не меняются. Общая вертикаль — внешние края `.faq-column`, поправка на scale и padding box абсолютного псевдоэлемента. Поэтому документные границы и padding не уводят guide внутрь.

## Контекст прямого входа — FUNC-024

`open(kind='properties', anchor)` начинает прежний transaction. Для appearance/reveal/menu панель PG остаётся hidden весь сеанс; используются существующие chooser-функции/слой. Выбор оформления/режима подтверждает сеанс через save/record. Для typography та же панель показывает только два textStyle; Back по решению пользователя отменяет сеанс. Прежний Back из расширенного PG сохраняет draft и возвращает в main.

`entry={kind,anchor}` определяет возврат/позицию/активную команду через surfaceChanged, без второго draft. Повторный вход или переход к другой команде отменяет прежний сеанс. Галочка/app Save сохраняют через прежнюю валидацию и один шаг истории. Menu использует только lifetime/слой, строки сами не записывают документ, разрешённые действия передаются dispatcher FUNC-029; app Save просто закрывает меню. Внешний клик закрывает menu без передачи холсту; внешний клик PG по-прежнему блокируется.

Полная и сокращённая типографика используют question/answer. chooseTextStyle/chooseColor параметризованы для ответа; цветовая форма и её вложенная транзакция не копировались. Начальный вид ответа сохранён. Гарнитура read-only, нового списка шрифтов нет.

Состояние на 26.10.2026, FUNC-010/011/012. Описание существующего кода, а не утверждение о готовности всего стандарта PG.

## Реализованная основа и её границы

`property-grid.js` содержит фабрику `window.createFaqPropertyGrid(api)`. Сейчас `preview.js` создаёт один экземпляр для выбранного FAQ. Основной экран и три расширенных раздела используют одну оболочку, один обработчик команд и один сеанс. Отдельные окна не клонируются.

Дополнительно один переиспользуемый слой `.pg-aux` обслуживает все вспомогательные окна: цвет, текстовые стили, оформления, раскрытие, линии. Оба слоя используют `.pg-shell` и общие контролы. Один редактор цвета параметризован для трёх назначений; независимых копий редакторов/обработчиков нет.

Основа обслуживает FAQ и один его вложенный спойлер через адаптер FUNC-027. Универсального реестра всех объектов нет: одна фабрика, локальная конфигурация владельца и общий набор контролов, без массового рефакторинга.

## Оболочка

- Один `.property-grid` с `.pg-header` и прокручиваемым `.pg-body`, созданный непосредственно в `body`.
- Ширина 350 внутренних px; `position()` использует текущий scale внешнего экрана, фактический FAQ и границы viewport/холста. Позиция слева с зазором 8 px корректируется при нехватке места; внешний интерфейс повторно не масштабируется.
- Обновление при scroll/resize и изменении размера FAQ; окно не занимает место в потоке и не обрезается холстом. Высота ограничена, шапка остаётся вне внутренней прокрутки.
- Внешний клик не закрывает окно и не передаётся объектам холста. Галочка, крестик, Escape, возврат и сброс обрабатываются централизованно.

## Навигация

`level`: `main`, `spoilers`, `button`, `size`. `render()` меняет заголовок и содержимое, сохраняя тот же сеанс. Три перехода идут из основного уровня; «Назад» возвращает на него. Это не универсальный стек произвольной глубины. Вкладки `rest/hover/active` раздела кнопки меняют только отображаемое состояние, а не данные документа.

Вспомогательное окно не меняет `level`. `openChoice(options)` принимает вид/заголовок, ширину, исходный элемент, способ позиционирования и обработчики `click/confirm/cancel`. `closeChoice()` убирает содержимое и возвращает фокус исходному контролу, в том числе после перерисовки родителя. `positionChoice()` учитывает scale и viewport; большие окна карточек центрируются, компактные привязаны к контролу. Слой один — открытие другого сначала отменяет предыдущий выбор. Обработчики назначены один раз; временные oninput/AbortController очищаются.

## Черновик и применение

- `transaction = {id, original, draft}` создаётся один раз при открытии из актуальных настроек. Все уровни работают с `draft`; `original` — независимый исходный снимок сеанса.
- До сохранения модель документа не меняется. `paint()` использует черновик для временного оформления; отмена заново отображает сохранённую модель. Он обновляет фон FAQ, текст вопросов, параметры кнопки, профиль спойлеров и разделители, затем вызывает адаптер раскладки оверлеев.
- Галочка проверяет данные, записывает весь черновик в настройки привязанного ID, закрывает окно и вызывает существующий `recordChange(before)`. Один изменённый сеанс — один шаг; no-op без шага.
- Крестик шапки/Escape отменяют весь сеанс без истории. При активном вспомогательном выборе Escape сначала отменяет только его; при работающей системной пипетке сначала прерывает её. Локальная цветовая транзакция сохраняет исходные `color/opacity`, применяет валидный preview к черновику и восстанавливает их при отмене. Галочка цвета не закрывает PG; крестик PG откатывает и подтверждённые вложенные изменения.
- «Сохранить» приложения сначала вызывает `save()`, затем включает preview; при ошибке остаётся в режиме редактирования. При открытом PG глобальная история заблокирована, ввод в текстовых полях не должен перехватываться.
- `selectionChanged()` отменяет сеанс при другом выборе/ID. Защитные ветки отсутствующего FAQ/удаления всего контейнера отдельно в браузере не проверены: таких команд пока нет.

## Общие контролы

Внутренние помощники модуля: `action`, `unavailable`, `row`, `card`, `field`, `colorControl`, `liveCheckbox`, `chips`, `remove`, `arrow`. Они собирают одинаковые строки, карточки, сегменты, цветовые образцы и команды. `textStyles`/`textStyleCss`, `appearances`/`appearanceFont`, `glyphFor` и общий CSS используются и реальным FAQ, и демонстрациями. Пока это функции внутри фабрики, а не отдельная экспортируемая библиотека контролов.

Неподключённые элементы — disabled с подсказками. Используются локальные Inter/cbuc-icons/cbuc-icons24, оригинальные SVG и `property-grid.css`; библиотек/UI-kit не добавляли. Показанные в новых узлах состояния проверены отдельно: hover не выбирает сегмент/карточку, выбранность хранится в модели, цветовой образец 24→28 px. Полное соответствие всем непоказанным состояниям библиотеки не заявляется.

## Переиспользуемый редактор цвета

`colorEditors` задаёт `title`, `palette`, `allowNone` и `tabs` для `question`, `background`, `dividers`. `chooseColor(key, anchor)` берёт актуальные цвет/непрозрачность из общего черновика и привязывает одну и ту же форму к этому объекту. Палитры разные и соответствуют своим Figma-фреймам; сброс берёт подтверждённый `defaults()[key]`. HEX/процент не перерисовывают поле на каждом символе; невалидный ввод не попадает в данные, остаётся последнее валидное значение.

Чтобы добавить ещё одно цветовое свойство: определить его объект `color/opacity` и default, включить в `normalized`, добавить конфигурацию `colorEditors`, вывести `colorControl(key)` и добавить применение в `paint()`. Не копировать форму, обработчики, транзакцию или создание слоя. Для иного пути данных сначала расширить привязку существующего редактора, а не делать отдельную копию.

Настоящий EyeDropper вызывается только при наличии API и по пользовательскому клику; отключён иначе. Возвращённый цвет применяется только если тот же выбор ещё открыт; закрытие отменяет операцию. Реальная системная пипетка отдельно не автоматизирована. «Другой цвет», «Картинка» и другие форматы не выдаются за работающие.

## Карточки и независимые демонстрации

Карточки оформлений используют реестр `appearances`, общий `sampleList()` и те же правила геометрии/шрифтов/иконок, что реальный FAQ. Демонстрационные строки не попадают в документ. Карточки режима используют тот же `sampleList` и отдельный DOM-флаг `data-demo-open`; кнопка демонстрации обрабатывается раньше выбора режима и не меняет FAQ.

Для новой карточки: получить её макет/состояния и явный смысл, добавить описание в соответствующий реестр, использовать общий renderer и стили, определить применение в одном обработчике. Не добавлять независимую реализацию FAQ или новый глобальный обработчик на каждую карточку. Оформление заменяет базовый профиль спойлеров целиком по уточнению пользователя; несвязанные фон контейнера/разделители остаются. Реестры показывают только шесть утверждённых оформлений и два режима раскрытия.

## Опциональные свойства

Сохранённые поля: `settings.propertyGrid.background = {enabled, color, opacity}` и `dividers = {enabled, color, opacity, line, thickness, outer}`. Наличие редактора отличается от значения. Defaults подтверждены: фон показан без цвета; разделители выключены, solid, 1 px, #D2D6DA/100%, outer=false. Числа проверяются как конечные десятичные, толщина ≥0 px без придуманного верхнего предела.

Для опциональных групп крестик убирает редактор и возвращает чипсу. Исключение **фон** по новому указанию FUNC-013: строка всегда видна, background.enabled нормализуется в true для совместимости. Крестик clear-background появляется только при color!==null и сбрасывает цвет/непрозрачность в null/100; чипсы фона нет. Отмена всего сеанса возвращает исходные сохранённые настройки. Не распространять очистку значения автоматически на все будущие свойства без их правил.

Группа разделителей добавляется и удаляется из PG, управляет реальными границами списка и спойлеров. Внутри одна линия между соседними; outer добавляет сверху/снизу. При add/delete/D&D правила следуют за DOM, внутренние линии рамочного профиля не удваиваются. Для границ/скруглений/тени на основном уровне нет подробных редакторов; чипсы недоступны.

## Привязка к данным и история

`preview.js` передаёт адаптер: `editor`, `canvas`, `faqElement`, `getFaq`, `getMode`, `getSelection`, `finishEdit`, `snapshot`, `record`, `historyChanged`, `layout`. Документ остаётся в единой модели `state.faq`; отдельной параллельной истории PG нет. `restoreDocument()` и вставка нового узла вызывают `paint()` после изменения DOM. Выбор, режим, scroll и открытость ответов остаются состоянием просмотра.

Уточнение FUNC-027 заменяет прежний этап общих настроек: общая правка заменяет соответствующие индивидуальные параметры, несвязанные сохраняются. Индивидуальный сброс возвращает наследование FAQ; хранится разреженная карта изменённых путей. Старое копирование общих settings новым элементам не считается индивидуальным переопределением. Данные и черновик существуют только в памяти страницы, без localStorage или серверного сохранения.

# Стартовое состояние и жизненный цикл FAQ

Актуально28.10: общий системный переключатель содержит3 независимых ветки site/document/document-grouping. Третья получает собственную типовую тройку при первом входе; не заменяет одиночный document и не очищает его историю. Повторные входы сохраняют данные/режим/историю; reload сбрасывает все ветки и всегда запускает заполненный Builder FAQ. После группировки тройки Builder получает обычный state.faq с прежней функциональностью.

FUNC-033 не меняет запуск: пустая строка документа, новые пустые спойлеры и группировка существуют только в текущем сеансе. При reload demoSet отсутствует, Builder получает прежний заполненный FAQ, документ при первом выборе — прежний одиночный спойлер. Служебная подготовка тройки очищает лишь историю документа. Подробнее — [структурные демонстрации](grouping-demo.md).

## Два сценария — FUNC-032

При reload выбран «Вопрос-Ответ» с прежними заполненными данными. Текстовая ветка получает отдельный seed, закрытый выбранный самостоятельный спойлер и пустую историю; прошлое состояние обеих веток из storage не восстанавливается. В сеансе ветки сохраняют свои документы, историю, режим и прокрутку. Общий внешний экран теперь1900×900: продукт1600×900 плюс системная область300×900, единый fit. Все упомянутые ниже стартовые координаты продукта остаются логическими и масштабируются вместе с оболочкой. Подробнее: [сценарии](scenarios.md).

Прототип демонстрационный: обновление страницы восстанавливает типовой заполненный FAQ. Изменения сохраняются только внутри текущего сеанса.

При загрузке preview.js один раз строит независимые рабочие данные из неизменяемого demoSeed: три прежних типовых вопроса и существующие demoAnswers. Начальные настройки — прежние стандартные настройки PG. Режим edit, вопросы закрыты, выбран faq-main, обычный тулбар виден; PG, магазин, вспомогательные окна закрыты; история пуста. Начальная прокрутка помещает верх секции FAQ на200px ниже верха центрального холста, как3085:167302. Локальные шрифты учитываются при первом позиционировании.

makeFaq/makeItem — общая структура данных. Заполненная фабрика вызывается только при запуске; пустая фабрика — при добавлении из магазина. Пустой FAQ получает новый ID и три новых ID спойлеров, пустые question/answer, закрытые ответы и независимую копию исходных настроек. «Вопрос 1–3» — отдельные редакторские placeholder, не текст документа. При обычном добавлении спойлера используется прежнее «Введите вопрос».

Три состояния: исходный заполненный FAQ; faq=null и область вставки faq-slot-main; вновь созданный пустой FAQ. Область вставки не хранит FAQ или его удалённые данные. Фото, заголовок секции и контакты не удаляются. DOM-оболочка FAQ с общими обработчиками переиспользуется, при отсутствии объекта отсоединена от документа; представления удалённых спойлеров и их ссылки очищены. Данные удалённого объекта остаются только в снимке Undo.

Тулбар FAQ → delete закрывает сеанс PG с отменой, завершает текстовый ввод, снимает drag/слои, удаляет FAQ с вложенными элементами и выбирает область вставки. Это один шаг истории. «Удалить» контекстного меню FAQ остаётся заглушкой. Добавление FAQ с тремя спойлерами — один шаг; Undo возвращает область вставки, Redo — тот же созданный объект с теми же ID. Счётчики ID не откатываются, поэтому последующее новое создание не использует старые ID.

Магазин один: createWidgetStore в widget-store.js. Открывается из области вставки или плюсом сайдбара, перекрывает холст справа (350px, отступ54px, top44px/bottom8px), не меняет масштаб или ширину холста. Есть локальный поиск по названиям и захваченная цель вставки. По уточнению пользователя прокрутка и скроллбар убраны; содержимое обрезается границей панели, колесо не прокручивает холст. Поиск позволяет отфильтровать карточки. При занятом месте плюс не открывает магазин, сохраняя hover и пояснение; после удаления FAQ снова доступен. Существующий FAQ не заменяется. Другие карточки, кнопки раскладок, маркеры и сокращённый тулбар — демонстрационные, без изменения документа. Подписи средних карточек выровнены влево и по вертикальному центру, нижний внутренний отступ содержимого8px, поиск не получает фиолетовую рамку. Плюс имеет active/hover/active-hover; повторный клик или Escape закрывает магазин. Неактивный плюс не закрывает PG и не отменяет его черновик. Открытие PG закрывает магазин. Открытие, поиск, hover и закрытие не записываются в Undo.

Сохранить → preview и Изменить → edit сохраняют текущий сеанс, не вызывают demoSeed или makeFaq. По согласованному ответу пользователя в preview область вставки и подсказки пустых вопросов скрыты; реальное содержимое не подменяется. Магазин и удаление недоступны. Новая загрузка всегда возвращает типовой экран edit.

Восстановления документа из localStorage/sessionStorage/сервера не было и не добавлено. Хранилище браузера не очищается, несвязанные ключи не затрагиваются. Рабочие данные, черновики и Undo/Redo живут только в памяти страницы.

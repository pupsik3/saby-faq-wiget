# Демонстрационные сценарии — FUNC-032/033

## Последнее уточнение текстовой группировки

Уточнение 28.10.2026: в отдельном сценарии «Три спойлера для группировки» функциональны только выбор, Ctrl/Cmd-выделение, группировка/разгруппировка и их Undo/Redo. У группы и её детей отключены ввод, раскрытие, PG, типографика, пресеты и структурные команды добавления/удаления; видимые команды остаются заглушками. Тулбар FAQ в этом текстовом окружении без первой команды «Назад». При группировке применяется существующий FAQ-пресет «В рамке»: общая рамка1px, радиус8px, внутренние разделители, отступы12px; отдельные рамки строк не дублируются. При разгруппировке возвращается исходное оформление самостоятельных спойлеров (рамка1px/радиус6px/отступы10px). ID, содержимое и порядок сохраняются. Полноценный FAQ Конструктора после обратной группировки и основной одиночный спойлер не ограничиваются этим правилом.

Описание ниже отражает предыдущие этапы; при расхождении действует это уточнение.

Актуально28.10: в одном системном переключателе три независимые ветки — «Вопрос-Ответ» (site), «Спойлер» (document), «Три спойлера для группировки» (document-grouping). Каждый текстовый документ создан одним buildDocument(id) и createWidgetScenario, без копии редактора; documents Map хранит отдельные runtime. Данные, режим/история и прокрутка не смешиваются. Первый вход третьей ветки подготавливает её тройку, последующие входы сохраняют результат. Reload стартует заполненным FAQ и сбрасывает все три ветки. В Builder после группировки возвращается полноценная обычная FAQ-модель; в текстовой группировке сохраняется оформление.

Структурные переходы FUNC-033: [создание из пустой строки, подготовка тройки, группировка и разгруппировка](grouping-demo.md). Они используют тот же рендерер и историю; ограничения контекста `grouping-demo` относятся к отдельным разгруппированным элементам, но не к повторно сгруппированному FAQ Builder. Стартовое заполненное состояние не изменено.

Прототип демонстрационный: обновление страницы восстанавливает типовой заполненный FAQ. Изменения сохраняются только внутри текущего сеанса. Стартовая ветка всегда «Вопрос-Ответ», edit, три прежних закрытых вопроса/ответа, выбран FAQ, история пуста, панели закрыты. Текстовая ветка получает собственный исходный документ при первом входе; обновление сбрасывает обе ветки.

## Оболочка и сеансы

scenario-shell.js создаёт системную область вне продукта и лениво подключает текстовый документ. Продукт —1600×900, системная область —300×900, общий внешний экран —1900×900. frame-fit.js применяет одно пропорциональное вписывание и центрирование; внутренние размеры продукта не уменьшаются. PG/меню/выборы ограничены активным продуктовым прямоугольником; T совмещается по центру с Back.

У каждого экземпляра собственные данные, режим, выделение, история и scrollTop. Переключение завершает текущий текстовый ввод, отменяет PG и вложенные цвета, закрывает меню/магазин и drag, затем восстанавливает другую ветку без старых окон. Переключение не записывается в историю. Глобальные клавиши и захват событий проверяют активность экземпляра. Save/Edit меняет только активную ветку; данные не восстанавливаются из storage и не сбрасываются при обычной перерисовке.

## Самостоятельный спойлер

Один общий рендерер строит заголовок, кнопку, ответ, редактирование и overlay. Собственная DOM-обёртка standalone-frame нужна только для размещения в статье; она не создаёт контейнер FAQ в данных. Добавление вставляет новый самостоятельный объект после целевого ID с пустыми текстами и новым ID; удаление сохраняет абзацы статьи. Обе операции используют общую историю. После удаления последнего элемента нет области вставки Конструктора; восстановление через Undo или reload.

Полный PG использует существующие typography/button/size/styleCard/color/line/chips, собственный original/draft и ту же историю. Прямой T содержит только две группы; Back отменяет и закрывает. Back из PG сохраняет черновик и возвращает в main. Общие правила кнопки, опциональных границ/радиуса и фона не изменены. Текст-ссылка скрывает строку кнопки, но сохраняет T. Размеры read-only, замок и две кнопки размера в шапке кнопки визуальные; тень, отдельные стороны/углы и выбор гарнитуры остаются недоступны.

Шесть пресетов меняют собственную модель спойлера: стандартный; текст-ссылка; акцентный заголовок (без вертикальной линии всего спойлера в новом образце); рамка с радиусом и линией между заголовком/содержимым; подложка; акцент содержимого. Рамка/радиус относятся к spoilerStyle, а не к faqStyle. Превью содержит один спойлер с отдельным демонстрационным текстом, реальный ответ не подменяется. Разделителей списка в этом контексте нет. Режимы inline/overlay используют общую механику; overlay в preview не сдвигает вопрос и статью, собственные фон/границы/отступы сохраняются.

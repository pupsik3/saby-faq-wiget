# Постоянные правила проекта

- Сохранять текущий стек: HTML, CSS, обычный JavaScript и сервер Node.js без фреймворков. Запуск: `node server.cjs`.
- Сохранять принятый дизайн, исходные ресурсы и локальные шрифты. Accordion-Font пока не использовать.
- Шрифтовые иконки не должны выделяться курсором как текст: применять `user-select: none` к иконкам и их содержимому. Обычный текст оставлять выделяемым.
- Сохранять базовую композицию 1600 × 900 и механизм её пропорционального вписывания: горизонтальное центрирование, привязка к верхнему краю, увеличение выше 1 и пересчёт при resize.
- Не перечитывать Figma без необходимости; сначала использовать существующие файлы проекта.
- Не устанавливать зависимости без согласования с пользователем.
- Реализовывать только текущую задачу. Не выводить назначение функций из изображений иконок.
- Проверять изменённое поведение и связанные ранее работающие сценарии, включая вписывание, если оно затронуто.
- Сообщать только фактически выполненные проверки. Не утверждать, что браузер проверен, если проверка не выполнена.
- В отчёте кратко перечислять изменения, проверки и ограничения; не выводить файлы целиком.
- Перед реализацией окон свойств учитывать [правила Property Grid](docs/property-grid-rules.md).
- Новые окна свойств собирать на [общей основе](docs/settings-architecture.md), не копировать целые окна и обработчики; уникальную логику добавлять только по необходимости.

- Внутри каждой группы строк PG колонка лейблов общая, по самому длинному отображаемому названию; редакторы выровнены по единому началу. Разные группы рассчитывают выравнивание независимо.

- Служебные фиолетовые рамки FAQ и спойлеров независимы от оформления документа: всегда 1 px, радиус 2 px. Настраиваемые границы и скругления их не меняют.
- Левые и правые края служебных рамок спойлера, FAQ и колонки с заголовком совпадают; реальные границы и внутренние отступы не смещают эти служебные вертикали.
- При загрузке страницы восстанавливать заполненную демонстрацию; изменения живут только в сеансе — [стартовое состояние](docs/demo-startup.md).

- Демонстрационные сценарии (FAQ, одиночный спойлер, текстовая группировка), их независимость и запуск описаны в [карте сценариев](docs/scenarios.md); продукт1600×900 и системная область300×900 используют единый внешний масштаб.

- Общие исправления применять к обоим демонстрационным сценариям; ограничивать одним только при явном указании пользователя.
- Ограниченные структурные переходы и возможности демонстрационного набора — [группировка и вставка](docs/grouping-demo.md); не расширять их до универсального редактора.
